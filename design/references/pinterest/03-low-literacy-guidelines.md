# Pattern 3 — Low-literacy interface rules: minimal, recognisable, plain-language

**Concrete visual pattern:** one idea per screen; generous whitespace; short, direct sentences; icons paired with visible words (never icon alone); recognition instead of recall (choices shown, not remembered); system status always visible ("Enregistré", "En attente d'envoi"); error prevention through input constraints and confirmation summaries.

**Why it fits ACSF:** the user brief explicitly says low literacy and French-language staff. These guidelines are evidence-based rather than stylistic: reduce what must be read, keep familiar words, show state, and avoid relying on memory. They also improve accessibility for everyone at a fixed 12px type size.

**Sources:**
- "Interface design guidelines for low literature users: a literature review", ACM DOI 10.1145/3578837.3578842: https://dl.acm.org/doi/fullHtml/10.1145/3578837.3578842 — nine guidelines including minimalistic design, limit on-screen information, visual cues used judiciously, recognition over recall, clear/direct language, simple navigation, visibility of system status, error prevention.
- GOV.UK Service Manual, "Writing for user interfaces": https://www.gov.uk/service-manual/design/writing-for-user-interfaces — "minimise cognitive load ... using the same language as your users ... inclusive for people who struggle with reading or have limited English"; prefer short direct copy.
- GOV.UK Service Manual, "Error messages": https://design-system.service.gov.uk/components/error-message — plain English, positive wording, no jargon, match the message to the field label.
